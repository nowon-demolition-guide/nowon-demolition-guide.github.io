## 포함된 파일

- `index.html`: 시맨틱 HTML, 원고/상담 연결, 메타데이터, JSON-LD
- `style.css`: 데스크톱·태블릿·모바일 반응형 디자인
- `script.js`: 모바일 메뉴 제어
- `assets/`: 생성 이미지(WebP), 실제 시공사례 2쌍(WebP), SVG 로고
- `favicon.ico`, `favicon.png`: 브라우저 및 검색엔진용 파비콘
- `robots.txt`, `sitemap.xml`: 검색엔진 수집 관련 파일
- `.nojekyll`: Jekyll 자동 처리 방지(필요한 경우)

**배포 ZIP을 압축 해제했을 때 최상위 폴더에 `index.html`이 있습니다.** ZIP 자체를 저장소에 올리는 것이 아니라 내용물만 저장소 루트에 업로드하세요. 숨김 파일 `.nojekyll`은 업로드 도구에 따라 표시되지 않을 수 있습니다.

## GitHub 저장소에 파일 업로드

1. GitHub에서 본인이 선택한 조직 및 저장소를 준비합니다. 조직 사이트 형식이라면 저장소 이름은 `nowon-demolition-guide.github.io` 입니다.
2. 저장소의 `Add file → Upload files`를 선택합니다.
3. 압축 해제한 파일 및 `assets` 폴더의 내용을 **저장소 최상위**에 업로드하고 `Commit changes`로 저장합니다.
4. GitHub 저장소는 정적 웹소스 버전 관리용으로 사용하는 것을 권장합니다.
5. GitHub Pages는 상업적 거래를 유도하는 사이트의 호스팅이 제한됩니다. 이 페이지는 **견적 상담 전환을 주목적으로 하는 영업 홈페이지**이므로, 공개 운영은 해당 목적의 사용이 허용되는 Netlify 등 정적 호스팅 플랫폼의 최신 이용약관을 확인한 뒤 진행하세요. 현재 선택하신 `.github.io` 주소는 호스팅에 사용할지 별도 판단이 필요합니다.

## 실제 배포 주소와 SEO 설정

아래 파일들은 사용자가 알려 준 조직 사이트 주소인 **`https://nowon-demolition-guide.github.io/`** 를 대표 주소로 전제하여 구성했습니다. 제작 당시 이 주소는 웹에서 404로 확인되어 실제 공개 여부를 보장할 수 없습니다.

실제 홈페이지를 Netlify 등의 별도 도메인에 게시할 경우, **배포 전** 아래의 모든 절대 URL을 실제 대표 주소로 일괄 변경해야 합니다.

1. `index.html`의 `<link rel="canonical">`, `og:url`, `og:image`, 파비콘 절대 URL
2. `index.html`의 JSON-LD `WebSite`, `WebPage`, `Organization`, `Service` 객체의 `@id`, `url`, 이미지 URL
3. `robots.txt`의 `Sitemap:` 절대 주소
4. `sitemap.xml`의 `<loc>` 절대 주소
5. 새 플랫폼이 **하위 경로**를 사용한다면 이미지·스타일·앵커 경로와 WebSite 사이트명 채택 제한을 따로 확인하세요.

동일 본문을 여러 개의 도메인에서 중복 배포하지 마세요. `noindex`는 설정하지 않았습니다.
